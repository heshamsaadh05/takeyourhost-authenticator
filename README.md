# TakeYourHost Authenticator

مصادقة ثنائية محلية لـ **WHM وcPanel**، بواجهة عربية وQR وإدارة لحماية حسابات الريسيلر وعملائه.

الإصدار: **2.1.0**. المستودع خاص؛ تحتاج صلاحية GitHub لتنزيله. لا توجد خدمة OTP خارجية أو اشتراك SMS.

> إضافة أمنية مخصصة، وليست منتجًا معتمدًا من cPanel أو بديلًا عن معالجة اختراق الخادم. جرّبها على بيئة اختبار أولًا، واحتفظ بجلسة root عبر SSH مفتوحة أثناء التثبيت والاختبار.

## المميزات

- نفس تطبيق Authenticator للمستخدم في WHM وcPanel، مع تحقق مستقل لكل جلسة.
- QR يُولَّد محليًا داخل الخادم، أو إعداد يدوي بالمفتاح. لا يُرسل المفتاح لموقع توليد QR.
- تشغيل/إيقاف عامل الحساب، أو حماية cPanel فقط، بعد التأكيد برمز حديث.
- تحكم root في تشغيل الإضافة على مستوى الخادم دون حذف عوامل المستخدمين.
- الريسيلر يتحكم في تحدي cPanel لحساباته المملوكة له فقط، بتأكيد عامل الريسيلر نفسه، دون عرض مفاتيح العملاء.
- استبدال التطبيق مع الاحتفاظ بالمفتاح القديم حتى تأكيد الجديد، وتجديد رموز الاسترداد.
- منع إعادة استخدام الرمز، وتقييد المحاولات، و10 رموز استرداد أحادية الاستخدام.
- لا يحتاج IP ثابتًا. لا يُعدّل المواقع أو قواعد البيانات أو إعدادات البريد.

## المتطلبات والتوافق

- Linux مع WHM/cPanel **134 أو أحدث** وواجهة **Jupiter**.
- Python **3.9+** وPerl المرفق مع cPanel. لا يحتاج تشغيل الإضافة إلى `pip install`.
- صلاحية root عبر SSH، وGit لتنزيل المستودع.
- خدمة cpsrvd تعمل وتدعم graceful reload، والوحدات الأصلية اللازمة متاحة، ومنها `Cpanel::Session::Restore` و`Cpanel::TimeHiRes`.

الاختبار الفعلي للمكونات وتدفقات الدخول جرى على cPanel 134 / CloudLinux 9. لم يُثبت التوافق الفعلي مع جميع إصدارات وتوزيعات cPanel الأخرى. يفحص المثبّت المتطلبات ويرفض التركيب غير المدعوم قبل تغيير الإعدادات، ولا يحاول إصلاح ملفات cPanel أو الترخيص أو وقت الخادم.

## التثبيت بأوامر SSH

### 1. الوصول للمستودع الخاص

استخدم مفتاح SSH مخوّلًا بالقراءة للمستودع؛ يفضّل **Deploy key بصلاحية قراءة فقط** لكل خادم. أضفه من إعدادات المستودع إذا لم يكن لديك وصول جاهز. تحقق من هوية مضيف GitHub عند أول اتصال؛ لا تعطّل فحص مفتاح المضيف.

نفّذ كـroot:

```bash
git clone --branch v2.1.0 git@github.com:heshamsaadh05/takeyourhost-authenticator.git /root/takeyourhost-authenticator
cd /root/takeyourhost-authenticator
bash install.sh --dry-run
bash install.sh --yes
```

لا تنفّذ أمر التثبيت إذا فشل `--dry-run`. الخيار `--yes` يتجاوز سؤال التأكيد التفاعلي فقط، ولا يتجاوز فحوص الأمان أو التوافق.

بديل HTTPS إذا لم تستخدم مفتاح SSH:

```bash
git clone --branch v2.1.0 https://github.com/heshamsaadh05/takeyourhost-authenticator.git /root/takeyourhost-authenticator
```

عند طلب بيانات GitHub استخدم طريقة مصادقة مخوّلة للوصول للمستودع الخاص. **لا تضع PAT أو كلمة مرور في الرابط أو داخل أمر shell، ولا ترسلها في المحادثات.** لا تستخدم `curl | bash` أو تشغّل سكربتًا لم تراجعه.

إذا كان Git أو Python غير مثبتين، ثبتهما أولًا عبر مدير الحزم المناسب؛ المثبّت لا يضيف حزم نظام من تلقاء نفسه.

### ماذا يفعل المثبّت؟

1. يتحقق من root والتوافق والأذونات والمسارات وعدم وجود تركيب مجهول.
2. يحفظ نسخة خاصة بـroot من الملفات المتأثرة والإعدادات وحالة العوامل في:
   `/var/backups/takeyourhost-authenticator/`.
3. يثبت وحدات الإضافة ويسجلها في قوائم WHM وcPanel.
4. يضبط مفتاح السياسة المخصص فقط: `SecurityPolicy::TakeMFA`.
5. يحمّل cpsrvd عبر graceful المباشر فقط، **دون إعادة تشغيل قسرية أو fallback**. لا يعيد تشغيل LiteSpeed أو Apache أو MySQL أو البريد.

عند الفشل يحاول الرجوع للتركيب السابق، دون استبدال مفاتيح المستخدمين بنسخة أقدم. إذا تعذر التحميل أو الرجوع الآمن يتوقف ويُبلغ بمسار النسخة؛ لا يستعمل إعادة تشغيل قسرية.

> **التركيب اليدوي القديم:** إذا وجدت ملفات الإضافة مسبقًا دون سجل تثبيت يديره هذا المثبّت، فسيرفض الكتابة فوقها. لا تحذف الملفات أو حالة العوامل لتجاوز هذا الفحص. يلزم ترحيل مدروس يحافظ على الربط الحالي. أوامر هذه الصفحة للتركيب الجديد أو تحديث تركيب يديره هذا المثبّت.

## الاستخدام

### root والريسيلر

في WHM ابحث عن **TakeYourHost Authenticator** داخل Plugins. يمكنك:

- ربط تطبيقك، أو إدارة حماية حسابك إذا كان مربوطًا.
- إيقاف حماية الحساب أو استئنافها، وإدارة الهاتف ورموز الاسترداد.
- إدارة حماية cPanel للحسابات المملوكة لك والمسجلة مسبقًا.
- من root فقط: تشغيل أو إيقاف الإضافة عالميًا.

### العميل داخل cPanel

افتح **Security → TakeYourHost Authenticator**، ثم:

1. افتح Google Authenticator أو Microsoft Authenticator واختر إضافة حساب ومسح QR.
2. امسح الرمز المعروض؛ أو استخدم المفتاح اليدوي بنوع **Time-based**.
3. أدخل رمز التطبيق المكون من 6 أرقام لتأكيد الربط.
4. احفظ رموز الاسترداد العشرة خارج الخادم؛ تظهر مرة واحدة فقط.
5. اختبر من نافذة خاصة، وانتظر **الرمز التالي**؛ لا يُقبل الرمز المستعمل مرة ثانية.

لا ترسل صورة QR أو المفتاح أو رموز الاسترداد. لا تبدأ الحماية قبل تأكيد رمز صحيح. يجب أن يربط كل عميل تطبيقه بنفسه أولًا؛ لا تُنشأ مفاتيح للعملاء نيابة عنهم ولا يتم تفعيل الحسابات تلقائيًا بمجرد التثبيت.

### فروق التشغيل والإيقاف

| الإجراء | الأثر |
| --- | --- |
| إيقاف عامل حسابي | يوقف العامل المخصص للمستخدم في WHM وcPanel، مع الاحتفاظ بربطه. |
| إيقاف حماية cPanel فقط | لا يغيّر إعداد حماية WHM. |
| تحكم الريسيلر في عميل | يغيّر تغطية cPanel للحساب المملوك له فقط؛ لا يعرض أو يستبدل المفتاح. |
| الإيقاف العام من root | يوقف طلب العامل المخصص لكل الحسابات، مع بقاء مفاتيحها محفوظة. |

تشغيل cPanel لا يتجاوز الإيقاف العام للإضافة أو إيقاف العامل العام للحساب. الإجراءات الحساسة تتطلب رمزًا حديثًا أو رمز استرداد غير مستخدم وnonce للجلسة؛ الإيقاف يتطلب تأكيدًا صريحًا.

## التحديث

اختر إصدارًا موثوقًا وراجع تغييراته، ثم بدّل قيمة `NEW_VERSION` بالإصدار المطلوب:

```bash
cd /root/takeyourhost-authenticator
NEW_VERSION=v2.1.0
git fetch origin --tags
git checkout "$NEW_VERSION"
bash update.sh --dry-run
bash update.sh --yes
```

التحديث لا يكتب فوق ملفات مفاتيح المستخدمين أو يعيد تفعيل إضافة أوقفتها من اللوحة. سيرفض الملفات المثبتة المعدّلة محليًا بدل استبدالها بصمت. لا تستخدم `git reset --hard` للتخلص من تعديلاتك.

## الحالة والاسترداد عبر SSH

```bash
cd /root/takeyourhost-authenticator
python3 scripts/manage.py status
/usr/local/sbin/take-mfa-admin status
```

الأمر الأول يعرض حالة التركيب المُدار؛ لا يعني أن كل حساب فعّل التطبيق. الثاني يعرض أسماء الحسابات المسجلة، وليس المفاتيح.

عند فقدان هاتف root ورموز استرداده، من جلسة root SSH آمنة:

```bash
/usr/local/sbin/take-mfa-admin reset root root
```

**تحذير:** هذا يعطّل العامل المخصص لـroot وحده ويحذف ربطه واعتماد جلساته، دون تغيير كلمة المرور أو حسابات الآخرين. أعد ربط تطبيق جديد فورًا من WHM. لاسترداد مستخدم آخر استبدل كلمتي `root` باسم المستخدم نفسه. لا تعالج تلف الحالة بإنشاء `{}` فوق سجل المستخدمين؛ استعد نسخة موثوقة وراجع سبب التلف.

## الإزالة مع الاحتفاظ ببيانات العوامل

```bash
cd /root/takeyourhost-authenticator
bash uninstall.sh --dry-run
bash uninstall.sh --yes
```

تزيل السياسة والروابط وملفات الإضافة، وتحتفظ بمجلد `/var/cpanel/take-mfa` ونسخ الأمان. **بعد الإزالة لا تعود الإضافة تفرض المصادقة المخصصة**؛ احتفاظها بالمفاتيح لا يعني استمرار الحماية. لا تغيّر المصادقة الأصلية أو كلمات المرور أو المواقع.

## حدود الحماية والاختبارات

رموز API مستقلة ولا تطلب رمز الهاتف؛ أمّنها وحدد صلاحياتها ودوّرها عند التسرب. طلبات API بكلمة المرور/Basic أو legacy access hash لا تتجاوز عامل الحساب المسجل؛ استخدم API tokens للتكامل الآلي قبل تفعيل العامل. لا تشمل الإضافة SSH أو Webmail أو FTP أو SMTP/IMAP.

المفاتيح محفوظة في ملفات root بصلاحية 0600 داخل مجلد 0700، لكنها **ليست مشفرة إضافيًا أثناء التخزين**. النسخ الاحتياطية تتضمن مفاتيح؛ احمها ولا ترفعها إلى GitHub. لا تعالج الإضافة اختراق root أو الترخيص أو السمعة البريدية. اقرأ [SECURITY.md](SECURITY.md).

اختبارات حزمة التثبيت وQR:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r tests/requirements.txt
sudo .venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

اختبارات المكونات الأصلية على خادم cPanel متوافق، كـroot:

```bash
bash scripts/test-cpanel.sh
```

هذه الاختبارات تستعمل حالة مؤقتة ولا تُنشئ حسابات استضافة أو تغيّر عامل مستخدم حقيقي. اختبارات GitHub Actions لا تمثل خادم cPanel فعليًا؛ اختبارات المثبّت تستخدم وجهات مؤقتة وأوامر cPanel مُحاكاة.
